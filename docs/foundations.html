Chapter 2

Building Blocks:
Images, Containers & Volumes

Understanding the difference between an Image and a Container is the key to mastering Docker. Let's break down the core components you will interact with every day.

1. The Dockerfile (The Recipe)

A Dockerfile is simply a plain text file containing a list of instructions. It is the automated script that tells Docker exactly how to build your environment from scratch.

# 1. Start with a tiny Linux filesystem toolset
FROM alpine:latest

# 2. Run a command during the build to install software
RUN apk add --no-cache nginx

# 3. Copy files from your host computer into the environment
COPY ./index.html /var/www/html/index.html

# 4. Tell Docker what process to launch when a container starts
CMD ["nginx", "-g", "daemon off;"]

2. Images & Layers (The Blueprint)

When you tell Docker to "build" that Dockerfile, it creates an Image. An Image is a highly compressed, read-only template.

Docker Images are built using a Union File System. This means the image isn't just one big file; it is a stack of Layers. Every instruction in your Dockerfile creates a brand new layer on top of the previous one. Because they are layered, Docker caches them to build incredibly fast!

# Read your Dockerfile and build an Image tagged as 'my-web'
$ docker build -t my-web .

# See all downloaded and built images on your host machine
$ docker images

3. Containers (The Running Process)

If the Image is the blueprint, the Container is the actual house. A container is a live, running instance of an Image. It is literally just an isolated process running on your kernel.

Copy-on-Write (The Read-Write Layer)

Because Image layers are strictly read-only, Docker places a thin, empty Read-Write Layer on top of the stack when a container starts. If Nginx needs to modify a config file, Docker copies that file up from the read-only layer into the read-write layer. When the container is deleted, this top layer is destroyed.

# Run a container from an image in the background (-d)
$ docker run -d -p 8080:80 --name website my-web

# Forcefully stop and remove a running container
$ docker rm -f website

4. Volumes (The Data Safe)

Because containers are temporary, their Read-Write layer is destroyed when they are removed. If you run a MariaDB database in a container, stopping it deletes your entire database!

Volumes solve this. A Volume is a managed folder on your physical host machine's hard drive. Docker creates a "window" linking a folder inside the container directly to this physical volume. Data is written to the host, bypassing the container entirely.

# Create a physical volume on the host
$ docker volume create db_data

# Mount (-v) the volume to a specific path in the container
$ docker run -d -v db_data:/var/lib/mysql mariadb
