Chapter 8

The Grand Finale:
A Packet's Journey

This is the ultimate test. Let's tie together the CLI, the kernel, the networking, and the daemons into one continuous, end-to-end timeline.

$ docker run -d -p 8080:80 nginx
1

The Request (User Space)

Your terminal's Docker Client translates the command and sends it down the UNIX socket. The dockerd daemon hears the request, downloads the Image, and hands the blueprint off to containerd.

2

The Kernel Magic

runc takes over. It talks to the Host Kernel to build the prison cell. It executes a chroot into the Image folder, locks the process in Namespaces so it thinks it is PID 1, and limits it with cgroups. Its job done, runc exits.

3

Network Plumbing

dockerd creates a virtual veth cable, plugging it into the docker0 switch and the container (as eth0). It assigns a private IP and writes a NAT rule in the host's firewall to catch port 8080 traffic.

4

The Handoff & Traffic

A containerd-shim steps in to babysit the Nginx process. When a user visits your host IP on port 8080, the Host's NAT intercepts the packet, translates it, and pushes it down the veth cable directly into the running Nginx container!

You have successfully mastered the architecture of Docker and the Linux Kernel. You are officially ready to build your custom infrastructure.
